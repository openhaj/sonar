blåsix checks a C library against the standards themselves. There is no reference libc: what a libc must provide, and how it must behave, comes from ISO C and POSIX.1. Any libc can be checked against any edition, whether it is glibc, musl or hajlibc.

One run, one target

A run checks one libc against one target: an edition of the C standard (C99 to C23) or of POSIX.1 (2001 to 2024), optionally with POSIX option groups such as XSI, and optionally with the GNU and BSD extensions. The target decides everything: the feature-test macros every test is compiled with, which interfaces are required, and which tests run. A header that hides a required interface under those macros is non-conforming, and it shows.

What it measures

  • Probes: for every required interface, a tiny program is built against the libc to see whether the header declares it and the library defines it (ok, undeclared or unlinked). Functions are probed as (name), which also catches a function-like macro with no real function behind it.
  • Tests: each runs in its own process and ends as pass, fail, skip, crash, timeout, error or unavailable (did not build). Every test cites the clause of the standard it checks.
  • Conformance per header: how many required interfaces are present, tested and verified (present and passing every test), with the lists of what is missing, failing or untested.
  • Coverage: with an instrumented build of the libc, the line coverage of its sources reached by the suite.

Results are written as results.tsv and results.json, one directory per libc and target, so several of them live side by side and two libcs can be compared on the same target.

Design

  • The test framework does not depend on the libc under test: raw write(2), tests registered in their own ELF section rather than with constructors, its own formatting.
  • The runner is built with the host libc: processes, timeouts, parsing and statistics live outside the libc under test.
  • One process per test, one binary per function: crashes are isolated, and a missing function is a result, not a build failure.

Testing a libc

A libc is described by a small profile (mk/libc/<name>.mk) that says how to compile and link against it; profiles for the host libc, musl and hajlibc are included. 

make run                                # host libc, POSIX.1-2024 + XSI
make run LIBC=hajlibc                   # hajlibc
make run LIBC=musl STD=posix-2008 OPTS= # another edition, no XSI
make compare A=host B=hajlibc           # same target, two libcs
make coverage LIBC=hajlibc              # line coverage of the libc sources
